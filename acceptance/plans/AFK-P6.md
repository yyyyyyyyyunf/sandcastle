Interface direction: add a bounded versioned `preparation` command before allocation, sharing owned host-process transport with verification. A generic run decision carries opaque metadata; no-work/blocked end without agent invocation. Add `iterationOutput` using the existing Output definitions for guarded runs; retain the legacy `output` option and its single-run retry semantics. Reject conflicting options early. This keeps per-iteration results separate from the old required `RunResult.output` contract, including the valid zero-agent case.

Require verification for preparation/per-iteration extraction, zero extraction retries, and an explicit supported branch/artifact setup. Reject mixing legacy output with the guarded extractor. New native mode must not implicitly resume a previous ticket. Keep the legacy output API compatible, but attach recovery references to its final extraction errors; its post-merge semantics are not the unattended path.

Prompt handoff must carry actual allocated source identity, target baseline, host iteration ID and metadata. Preserve inline prompt literal semantics and existing file expansion; expose dynamic handoff through an explicit native argument/file contract rather than relying on a predicted temporary branch name. Persist preparation and per-iteration outcome before the next allocation. The P4 checker receives extracted `result.output` and the original metadata.

Preparation decisions need their own journal records so the final no-work check does not masquerade as an agent iteration. Generate the ID before that record, bind the prepared target branch/revision through allocation and lifecycle startup, and retain the original metadata. Seal complete raw output before extraction so failed extraction remains diagnosable. In prepared mode, completion tokens request agent shutdown while accepted results return to host queue preparation; host decisions govern progression. Publish a protocol capability constant for P7 to reject older packages before agent allocation.

Use real native fixture processes and Git/Backlog for the shared-command integration, with existing failure seams for record/cleanup faults and real owned-process checks for preparation cancellation. Tests use the installed skills path explicitly, not a copied checker. Record current tool versions for each repository; the shell resolves different Node versions in skills and the temporary Sandcastle worktree. P7 supplies generated project wiring; P8 tests the packed public artifact with Kimi.

Independent two-axis review precedes final gates and the P6 report. Raw evidence: Sandcastle `acceptance/runs/AFK-P6/`. Update ADR 0010 (legacy versus per-iteration output) and ADR 0019 (confirmed termination); document capability requirements and native protocol compatibility. Do not claim P7/P8 completion from fake-agent integration tests.
