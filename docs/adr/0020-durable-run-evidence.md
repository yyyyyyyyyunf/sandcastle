# Durable evidence snapshots and run records

Declared gitignored evidence must remain readable after its worktree is removed. Add opt-in `artifacts: { root, paths }` to agent run entry points. The agent writes ordinary repository-relative paths. Sandcastle copies them from the host worktree into `<root>/<run-id>/<iteration-id>/`, preserving relative names, after execution stops and before host merge. Each run owns an exclusive directory; snapshots never replace an existing destination. Sources must be regular files/directories within the worktree, and cannot include `.git`, `.sandcastle`, parent traversal or the artifact root itself. Isolated providers cannot export arbitrary directories through their current public copy interface, so this mode rejects them before agent execution.

`run.json` in the run directory records iteration identities, worktree paths, candidate and merged revisions, artifact roots, errors and cleanup state. Writes use an exclusive temporary file, file synchronization and rename. A record with recovery references is persisted before source cleanup; the cleanup result and final run status are written before another iteration. If a post-cleanup record update fails, the earlier record still contains the candidate/merged revisions and exported artifacts needed to recover. This is a process-lifecycle guarantee, not a claim of transactionality between Git and the filesystem under power loss.

Evidence or recording failure before cleanup retains the worktree even when Git is clean. Failed agent execution also retains its worktree in this mode; after sandbox release, confirmed-stopped execution may have its evidence exported during failure recording. Unknown termination leaves the source in place without claiming a stable snapshot. A failed cleanup is distinguished from a preserved source; its candidate and exported artifacts remain recovery references.

Caller-owned worktree and reusable sandbox handles keep ownership of their directories. Their run record uses `caller-owned` for this boundary; a later manual `close()` is outside that run's cleanup record. Retention requested by an evidence failure propagates to the owning handle so that `close()` preserves the clean source.

All modes now accumulate `preservedWorktreePaths`; the legacy single field means the most recently preserved path. Error objects carry available recovery fields without losing their usual message/type. If an original primitive or frozen failure cannot carry fields, `RunRecoveryError` retains it as `cause`. Structured workflow acceptance and guarded merge decisions remain separate later additions; an exported artifact is not an acceptance verdict.
