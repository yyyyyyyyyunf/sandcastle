# Verify a candidate before host merge

Status: accepted for the AFK fork delivery.

An iteration-end callback is too late to reject a delivery if the lifecycle has already merged it and removed its source. Add opt-in `verification` at the lifecycle boundary after agent termination, synchronization, provider finalization and declared evidence export, before any merge, source detach/delete or worktree cleanup.

The host invokes an argv command using the same owned-process executor as noSandbox. Stdin is a version 1 `VerificationContext`: host-generated iteration ID, source branch and candidate commit, target branch and its baseline commit, host/worktree paths, durable artifact root and result file. The result file contains semantic stdout, complete raw stdout lines, session references and usage. Stream display tails do not define this input. A guarded result exceeding 16 MiB of raw stdout fails rather than silently truncating; the checker protocol is limited to 1 MiB. stderr is diagnostic, not a decision channel.

The checker writes one JSON object with `version: 1`, `decision: "accept" | "retain"` and optional opaque `outcome`. Sandcastle persists that decision before acting. Retain is a normal stop with `stopReason: "retained"` and preserved source even when Git-clean. Nonzero exit, malformed decision, timeout and changed Git state are distinct errors carrying recovery references. Timeout and cancellation wait for the invocation's process group to stop; unconfirmed termination takes precedence over ordinary abort reasons.

Guarded execution requires explicit merge-to-head and durable artifacts. Head and named-branch modes write directly to a delivery branch, so they are rejected before agent execution. Windows is rejected until process-group termination can be confirmed. Isolated providers remain subject to the artifact-export capability gap. Worktree runs and nested merge-to-head sandbox runs use the same boundary and preserve their owning handle when retained.

After acceptance, use Git reference transactions to verify and lock source HEAD and its commit, then target HEAD and its expected old commit. Check each symbolic branch identity while its HEAD is locked. Apply the fast-forward with `read-tree -m -u`, then commit the target reference update; source locks remain held throughout. A plain read followed by `git merge --ff-only` failed a real race fixture: an intervening target advancement could be accepted as the original baseline. The guarded path therefore uses Git's prepared transactions, with a shared ten-second bound and confirmed process cancellation. It requires Git 2.30 or newer. Git's [update-ref transaction](https://git-scm.com/docs/git-update-ref) verifies old values while preparing locks; [read-tree](https://git-scm.com/docs/git-read-tree) supports a two-tree fast-forward while protecting local changes.

Detected changes and failed updates stop with source recovery intact. If a filesystem/ref persistence failure occurs after checkout has started, the target working directory may need recovery; Sandcastle does not reset it automatically or proceed to another iteration. The persisted candidate and accepted-decision record remain available. Guarded updates use Git plumbing, so porcelain-only hooks such as `post-merge` do not run; reference-transaction hooks remain active. Unguarded merge behavior remains compatible. This boundary delegates business acceptance to the caller; Sandcastle does not interpret tracker state, ticket IDs or verdicts inside `outcome`.

Native task preparation and schema extraction per iteration are the next integration stage. Legacy post-run `Output` extraction is unchanged by this increment.
